# tarwin-net

IPv4/IPv6 UDP validation and output, registered receive constraints and fair-queue pacing. This is not a full TCP stack or NIC driver.

Run `swift test` on macOS. For an Embedded Swift object-only check, run `SWIFTC=/path/to/swift-6.3.3/usr/bin/swiftc ../tarwin-device/check-profile.sh "$PWD"`. Host tests and cross-compiled objects do not demonstrate a booted Tarwin kernel.

The interface transmit queue retains registered memory pins across driver restarts. It publishes only paced FIFO heads, lets foreground traffic bypass background traffic on congested links, and rejects completions from the previous driver epoch. Pending packets survive restart; already-published packets complete as lost only after the old DMA domain drains. The driver must retire its device mappings before releasing packet pins.

Each NIC hardware queue gets a fresh A.4 ring pair (64-byte records) per driver epoch. The producer publishes only a bounded frame IOVA and length, never a process's memory handle or kernel pin token. TX completions must match the publication's epoch, queue, ID and byte count; release waits for the mapping to retire. RX carries exclusive writable grants. Completion lengths cannot exceed the posted capacity, and the stack cannot consume bytes until DMA retirement/cache synchronization succeeds. Restart disables both directions; writable buffers are reclaimed only after the old domain drains. Pending TX retains its pins; a published TX frame is never replayed by the interface.

The Mac-hosted BlockQTest connects this interface/driver path to two QEMU NICs and delivers a checksummed IPv4 UDP datagram to a preposted endpoint receive on an isolated virtual link. Host callbacks supply pin/grant lookup; the test is neither a physical NIC run nor a guest network stack boot.

NeighborInterface forms ARP and IPv6 Neighbor Solicitations for routed on-link next hops and responds for its assigned address. Each interface/address/driver epoch has its own bounded NeighborTable. Only a live matching request can learn a unicast MAC. Neighbor Advertisements must be solicited, unfragmented, hop-limit 255, checksummed, and carry a matching Ethernet option. Unsolicited replies never replace a reachable entry. Retry and reachability deadlines use the caller's monotonic clock. This handles solicited next-hop resolution, not the full neighbor-unreachability state machine. Neighbor resolution alone does not authenticate peers.

RouterDiscovery takes an already assigned link-local address, an opaque interface identifier from address policy, and a router admission callback. It consumes unfragmented link-local advertisements with valid hop limit, checksum and option bounds. Router and autonomous /64 lifetimes age independently; the unauthenticated two-hour rule protects existing addresses. Tentative addresses are not usable until DAD probes have actually been sent and the receive interval has elapsed. Valid competing DAD probes or advertisements suppress the tentative address. The interface owner must join multicast groups, serialize inbound frames and timers, distinguish local multicast loopback, and discard state across link epochs. Default-router reachability selection, on-link routes, RFC 7217 identifier derivation, temporary addresses, extension headers and DHCPv6 are outside this mechanism.

The hosted `--neighbors` check solicits an independent libslirp router, configures the advertised prefix, transmits a DAD probe, advances QEMU's clock and uses the assigned address to resolve the gateway on all three machine models. No RA is generated by the test driver.

## TCP stream connections

`tcpSegment` checks whole IPv4/IPv6 packets, TCP data offsets, IP lengths, pseudo-header checksum and option framing before returning a view of the exact payload. It decodes SYN MSS/window-scale/SACK-permitted, timestamps and SACK blocks. IP options, fragments and IPv6 extension headers must be handled upstream. Parsed options are not by themselves evidence of negotiation or timestamp freshness.

`TcpReceiveWindow` is one established connection's bounded receive buffer. The connection owner must authorize the tuple (including interface/epoch), ACK, timestamp/PAWS and policy in the admission callback; SYN, RST and urgent data are not consumed here. Sequence arithmetic wraps, conflicting overlap preserves the first byte, a hole neither delivers bytes nor advances the cumulative ACK, and FIN occupies sequence space only once the gap closes. Out-of-order ranges are capped at setup; when full, a newly disjoint range stays unacknowledged. Negotiated SACK reports the most recently received range first, with at most four blocks fitted to option space. Only a successful stream read opens the receive window.

Mac tests include a thousand reordered/overlapping segments checked against a first-arrival oracle, wraparound, short reads and a zero window.

`TcpConnection` actively opens an IPv4 or IPv6 stream on a caller-authorized route. It advertises MSS and SACK, retains at most one unacknowledged segment, clips writes to the path MTU, peer MSS and advertised window, and frees only an acknowledged prefix. The retransmission timer uses RTT samples from unambiguous ACKs, bounded exponential backoff and a finite retry budget. It handles receive-side overlap, half-close, simultaneous FIN, TIME-WAIT, exact-sequence resets and challenge ACKs. Failed TX publication leaves control output retryable. One segment in flight is a conservative limit, not a production congestion controller.

Window scaling is offered independently in each direction. SYN/SYN-ACK windows are never shifted; lack of peer support caps the receive buffer at 65535 bytes. With scaling, receive storage is bounded at 1 MiB. Supply a private per-connection `timestampOffset` to offer RFC 7323 timestamps. When negotiated, non-reset segments must carry timestamps; PAWS rejects stale values using serial arithmetic and a 24-day validity limit. Echo updates follow the last *published* cumulative ACK rather than unacknowledged out-of-order data. An echo matching the last transmission can supply an RTT sample after a retry. Data and padded options share the path and peer MSS budgets.

If two active opens cross, each connection keeps its original SYN sequence
and responds with SYN-ACK, without entering a listener backlog. A full TX ring
leaves the reply pending. A matching crossed SYN-ACK, or the final ACK after
publishing a SYN-ACK, establishes the stream. Host tests exchange data in both
directions over IPv4 and IPv6 and cover a lost SYN-ACK. The libslirp tests
exercise ordinary active and passive opens, not simultaneous open.

The caller reserves the tuple, generates a private unpredictable ISS, serializes events and invokes `pump` on timers, writable notifications and input. The caller checks network grants, interface/epoch and egress pacing (including challenge-ACK rate limits) before every publication. Removal cancels the connection rather than rerouting queued bytes across a new grant. An application-level deadline or explicit abort remains necessary if a peer never lifts a zero window or never sends FIN. There is no SYN-data support, ECN, MPTCP, packetdrill conformance or native socket syscall binding here.

A write against a zero window can retain one new byte; a write-side close can retain FIN instead. Neither occupies sequence space before its first publication. If an existing flight encounters a window shrink, probes resend only the first unacknowledged byte. The persist timer starts at the RTO and backs off independently to 60 seconds. Valid zero-window replies keep the connection alive without postponing the next probe; unanswered probes are bounded by the configured retry budget. A Mac test drops the reopening update after draining a full receive ring and verifies that the original stream arrives exactly once.

`TcpListener` admits authorized SYNs only on a bound address, port, interface and epoch. Half-open records have a fixed backlog and lifetime and do not allocate stream buffers. Retries use the same ISS and bounded backoff. A valid third ACK (including data or FIN) promotes to a stream only when the caller has accept capacity. The owner reserves listening tuples, supplies entropy, serializes established/half-open demultiplexing and drains the listener on revocation. Wildcard binds are not supported.

`TcpService` queues completed streams in handshake order within a receive-buffer budget and keeps processing their data while no application is accepting. `EndpointAccept` checks the generated call, the submitting process’s typed listening Endpoint (Read), writable Port, server policy and exact 32-byte peer-address pin. It reserves Net completion credit before waiting. On success it installs the stream’s Endpoint in the same live process table with no more rights than the listening handle, and fills the peer address before the completion can be taken. A cancelled or closed-port operation exposes neither peer bytes nor a handle. Handle quota failures leave the stream queued.

The bootstrap still supplies the object registry, grant checks, VM pinning, locks and trap-provider binding. It serializes accepts in submission order, dispatches cancellation by operation token, and hands traffic to the child owner atomically with dequeuing.

`DatagramReceive` implements UDP Endpoint.receive and Endpoint.receiveFrom over retained Endpoint and Port handles. The worker admits complete datagrams only after checksum, tuple, interface generation and policy checks. Packet and byte limits bound the queue, including empty datagrams. A completion fills the pinned scatter buffers and optional source address, reports truncation in aux bit 0 and optionally returns the receive timestamp. Peek retains the whole datagram; WaitAll never joins messages. Cancellation or denial leaves both destinations and queue untouched.

UDP send/sendTo gather a whole datagram into bounded egress storage. The worker authorizes the route, enforces the endpoint binding and path MTU, and rechecks generation and policy before publication. A full queue waits; a failed NIC publication leaves the head intact. A successful Net completion releases the source pins, notifies how many bytes were staged and does not promise on-wire delivery. UDP corking is unsupported; this copying path is not large-buffer zero-copy TX.

UDP sendMany and receiveMany each reserve one completion and report a FIFO prefix in messages, not bytes. The submitter supplies pinned snapshots bounded by total message and vector limits. The worker updates only the completed 56-byte records: transferred length, flags and, for receives, source address. Untouched suffix records are reusable for the next call. Batch Peek observes distinct datagrams without removing them; a zero-byte datagram counts as one. Bootstrap still provides copy-in, VM pins, routing, endpoint lookup and serialization.

`EndpointReceive` reads an accepted stream into a kernel snapshot of writable, pinned scatter buffers. The handle needs Read, the port needs Write, and both accept and receive bind cancellation to the submitting process and handle name. The worker services receives in submission order. Peek leaves the advertised window unchanged. WaitAll waits for the pinned capacity or an earlier FIN, and is unsupported when the request exceeds the negotiated receive ring. Empty total capacity is invalid; a successful zero-byte result means EOF. Denied, cancelled and closed-port reads neither copy nor consume bytes. The worker rechecks policy and owns the pins until completion or withdrawal; this is not native VM pinning or a trap implementation.

`EndpointShutdown` is a synchronous two-register provider for connected TCP streams. Read, Write and Both require the corresponding endpoint rights; Both changes neither half unless both rights are present. Read discards unread bytes, completes pending reads with EOF, and continues acknowledging peer data without forwarding it to the caller. Write stops new sends immediately and uncorks accepted data. The worker pumps the final FIN after earlier bytes are acknowledged, including across a zero window. Success does not mean the peer has acknowledged the FIN. Composition must reschedule waiting I/O and TCP after a shutdown.

With `BlockQTest --tcp-listen`, a host client connects through a private Unix socket to restricted libslirp. Its independent TCP peer connects to the listener, receives the complete corked response followed by EOF, and acknowledges FIN on arm64, x64 and rv64 QEMU models. No TCP port is opened on the host.

`EndpointSend` uses the same stream grant and requires Write. A Net completion reports only the prefix copied into TCP-owned staging. The application may reuse those source bytes immediately; neither transmission nor peer ACK is implied. Staging adds at most one negotiated payload beside the existing flight. A full stage applies backpressure; send workers must service pending operations in order. More corks a partial payload for at most 200 ms from the first append. Push, a following non-corked send, a full segment, or a write-side finish releases the cork. The stream owner must pump on that timer and on egress/input events. A closed peer window uses the normal persist probe, and a failed publication leaves the staged prefix intact.

In `BlockQTest --tcp-receive` this connection exchanges binary data with restricted libslirp on a private pipe. The fixture drops the first outgoing data segment, advances the clock and checks that retransmission reaches the peer exactly as written; the peer acknowledges the FIN. QEMU 11.1.3 libslirp declined timestamps and scaling: these three models verify fallback, while host protocol tests verify negotiation, timestamp wrap/expiry, delayed ACKs and scaled windows. The route, ISS, clock and admission policy are test inputs, not a guest boot.
