# Tarwin implementation decisions — 26.11.1

TW-001 through TW-022 in [Appendix B](../../tessera/roadmap/Tarwin.md) remain normative. These choices resolve implementation details; none is a conformance waiver.

| Id | Decision | Reason |
| --- | --- | --- |
| SW-001 | Non-allocating Embedded Swift in IRQ, guest-exit, probe-hit and panic paths; Embedded Swift for the kernel; regular Swift for tvmm, compiler analysis, exporter, controller and tests. | No Foundation or hosted runtime in a kernel target. Host build and freestanding code generation are distinct checks. |
| BO-001 | Use TBIB revision 1; check producer train against the approved 52-train history. Validate the entire sorted, disjoint map and reserved fields before consuming it. | A valid prefix does not make the rest of the handoff trustworthy. See [boot decisions](../tarwin-boot/decisions.md). |
| BO-002 | Persist slot choice and attempt decrement before boot. Use recovery on exhausted attempts or malformed protected state; never advance the security floor from an unconfirmed candidate. | Preserve rollback and recovery semantics across power loss. |
| EX-001 | Number the 135 named public §23 calls from 1 in ASCII lexical order; zero is invalid. | The introductory count disagrees with the named list. Preamble aliases are not extra calls. |
| EX-002 | Generate train extensions separately from 0x10000; domain code references generated names. | Keep public ordinals stable within this train and avoid conflicting local allocations. |
| EX-003 | Use §23.3 VM/vCPU spelling, Probe.attach with last-close detach, and PerformanceSession.create/start/stop/read. | [One shared source](../tarwin-syscall/decisions.md) for the private ABI. A number does not install a handler. |
| EX-004 | Keep public Presence at 16; give Fence the private type 32. Do not expose it as a public handle type. | Distinguish nontransferable Presence and exportable fences; [object decision](../tarwin-object/decisions.md). |
| EX-005 | DeviceKit calls occupy a separate 0x10100 bank in the shared call index. | Preserve existing train call numbers. See [execution decisions](../tarwin-syscall/decisions.md). |
| HV-001 | Reserve/pin before installing mappings. Do not recycle guest memory, a slot, or its translation domain until all invalidations complete. | Stale translations must never reach new owners. Partial device assignment stays quarantined. |
| HV-002 | Require confidential-guest attestation; require independent support for the combination of nested and confidential. | Having each mode separately does not prove the combination is isolated. |
| VM-001 | Negotiate only implemented features on split queues. Snapshot descriptor metadata, pin guest-object spans, bound private I/O buffers and publish used entries after completion. | Unsupported packed/indirect descriptors cannot be interpreted as host addresses. |
| VM-002 | Bind a migration to an epoch; freeze CPUs/input/DMA before final capture and fence the source before durable ownership changes. | A lost commit acknowledgement must not create two live machines. |
| VM-003 | Bind Android surface routing and service grants to one sandboxed job, authenticated app, epoch and host-owned handles. | Android permissions are not host authority. |
| PR-001 | Analyze a structured postorder control-flow graph, charging the larger branch and full proven loop count. Reject unknown nodes, effects or bounds. | No profile escape through unexamined paths. A signed object also needs an immutable pin and matching hook/maps. |
| OB-001 | Publish a panic record with version, bounded length, CRC32 and last-written commit byte. Clear it only after archival succeeds. | Warm reset may interrupt either write or collection. CRC detects damage; it does not authenticate provenance. |
| OB-002 | Build debug transport inspection separately, with neither dependency nor entry point in release trace code. | A boot option must not enable a release-image debugger. |
| AC-001 | Block on any missing physical reference or independent workload result; compare ten-run geometric means per workload, build and serial. | Averages across machines or a portable unit test can hide a release regression. |
| HS-001 | The kernel stays the kernel: objects, handles, rights, IPC, scheduling policy, the loader, code-signing checks, TRFS and the network stack run in `tarwind`, from the same Tarwin packages. Only layer 0 (section 36.1) is replaced, by `tarwin-arch-hosted`. | TarwinHosted.md section 3 |
| HS-002 | One Tessera process is one macOS process (the task). | TarwinHosted.md section 3 |
| HS-003 | LibTessera apps run as their signed Tarwin ELF images. The task host maps them; nothing is relinked as Mach-O. | TarwinHosted.md section 3 |
| HS-004 | The gate is a combined `mach_msg` send and receive on the task's kernel port, with a send-once reply right. Arguments and results use the register layout of Tarwin.md section 10.2 in the message body. A blocking call is answered when it completes; it holds no `tarwind` thread meanwhile. | TarwinHosted.md section 3 |
| HS-005 | `svc #0` sites are rewritten at load. The loader reads the image's trap-site table (TVISA.md section 17.10) and patches each site to a branch to the gate stub before code is made executable. A `svc` not in the table raises SIGSYS in the task; the task host treats it as a Tarwin fatal exception (section 11.4), never as a system call. | TarwinHosted.md section 3 |
| HS-006 | Port rings (Tarwin.md section 10.5), the time page and all shared memory are macOS shared memory (`mach_make_memory_entry_64`) mapped into the task by the task host. Steady-state ring I/O makes no gate call, as on hardware. | TarwinHosted.md section 3 |
| HS-007 | `tarwind` never asks for another task's task port. The task host maps, protects, unmaps and starts threads in its own task on `tarwind`'s instruction, over the task's command port. `tarwind` trusts nothing the task host reports. | TarwinHosted.md section 3 |
| HS-008 | Every task runs under a generated `sandbox_init` profile: no file system, no network, no Mach lookups except `tarwind`'s service, no `fork`/`exec`. All authority arrives as handles from `tarwind`. | TarwinHosted.md section 3 |
| HS-009 | Images execute from `MAP_JIT` memory written once and sealed, after `tarwind` has verified the signature, train, CPU features and entitlements (Tarwin.md section 7.2). Tessera.app carries `com.apple.security.cs.allow-jit`. | TarwinHosted.md section 3 |
| HS-010 | Threads are host threads. `tarwin-sched` keeps the class, deadline and donation state; the hosted layer applies it with pthread QoS classes, `thread_policy_set` and work intervals (`os_workgroup`). XNU does the dispatching. | TarwinHosted.md section 3 |
| HS-011 | Storage is TRFS in `tarwind` over a file-backed block device: a sparse disk image in `~/Library/Application Support/Tessera/Disks/`, flushed with `F_FULLFSYNC`. A shared folder of the Mac's is a file-system server (Tarwin.md section 20.4) granted only through the picker. | TarwinHosted.md section 3 |
| HS-012 | Networking: Tarwin endpoints are backed by BSD sockets opened by `tarwind`, one per endpoint. Packet filtering and per-app rules run in `tarwind` before the socket call. No vmnet. | TarwinHosted.md section 3 |
| HS-013 | Graphics is Metal. The hosted GPU driver is a DeviceKit driver process that owns an `MTLDevice`; GPU buffers are `IOSurface`s, fences are `MTLSharedEvent`s exported as Tarwin fences (Tarwin.md section 22). Each MosaicDisplay output is a `CAMetalLayer` in a Tessera.app window. | TarwinHosted.md section 3 |
| HS-014 | Input, audio, power and sensors are hosted DeviceKit drivers fed by Tessera.app: `NSEvent` to HID, Core Audio to device streams, IOPowerSources to the power service. | TarwinHosted.md section 3 |
| HS-015 | Swift profiles follow Tarwin.md section 8.1: the gate stub and task-host entry are non-allocating Embedded Swift; the task host is Embedded Swift; `tarwind`, the hosted drivers and Tessera.app are regular Swift. | TarwinHosted.md section 3 |
| HS-016 | Apple silicon only. x64 Macs are not offered. | TarwinHosted.md section 3 |
| HS-017 | Hosted runs are extra evidence, never a substitute for the aarch64, x64 and rv64 results Tarwin.md section 1.4 requires. `BackendInfo.kind` stays Native; a new flag `HOSTED` reports the hosted kernel. | TarwinHosted.md section 3 |
